Earlier Python: turn a foot path into position targets

In the earlier Python trajectory path, I chose a foot position, solved geometric IK, subtracted a neutral reference, and converted the joint-angle changes to raw motor-position changes. The motor driver still closed its own joint loop; this describes the host trajectory commands.

Cycloidal swing-foot trajectory · 0 ≤ u ≤ 1
xswing = −L/2 + L[u − sin(2πu)/(2π)]
zlift = H[1 − cos(2πu)] / 2

L is step length, H is swing clearance, and u is normalized swing phase. This cycloidal foot-path shape is distinct from the cycloidal gearbox geometry.

From a geometric target to the motor
q(φ) = IK(p(φ))
Δq = q(φ) − IK(preference)
mtarget = mreference + σGΔq

σ is the configured motor sign and G is the gear ratio. This path sends a PDO2 position target with desired velocity set to zero. The Python implementation also has measured-position and telemetry readers.

leg_controller.py · output-joint delta to raw motor delta
def raw_delta_for_role(self, role: str, angle_delta: float) -> float:
    return get_motor_sign(self.name, role) * angle_delta * GEAR_RATIO

C++: command position and velocity explicitly

The C++ Cartesian path uses measured joint state to reconstruct foot position and velocity. It obtains desired joint positions from IK and desired joint velocities from the analytic Jacobian at the measured configuration. It then checks and stages the commands before transmission.

State reconstruction and command construction
p̂ = FK(qmeasured)
v̂ = J(qmeasured)q̇measured
qdes = IK(pdes)
q̇des = (JᵀJ + λ²I)−1Jᵀvdes

Damping reduces the velocity amplification that can occur when singular values are small, at the cost of tracking accuracy. Physical stability still needs to be tested.

LegController.cpp · solve instead of explicitly inverting
const Eigen::Matrix3d jacobian_transpose = forward_jacobian.transpose();
const Eigen::Matrix3d normal_matrix =
    jacobian_transpose * forward_jacobian +
    jacobian_damping * jacobian_damping * Eigen::Matrix3d::Identity();
return normal_matrix.ldlt().solve(jacobian_transpose);

This PDO3 Cartesian path sets feedforward torque to zero. Before transmission, the joint layer checks position, position error, velocity, and feedforward-torque bounds. Force and inverse-dynamics control are not implemented by this command path.

The equations changed with the conventions

The geometry and conventions changed along with the language. The old Python model uses millimetres and a +84.26 mm hip offset. The retained C++ model uses metres, signed ±0.07456 m offsets, and rigid transforms between the leg and body frames.

Compare equal geometry before comparing raw angle tuples
X = ℓt sin t − ℓs sin(s − t)
A = ℓt cos t + ℓs cos(s − t)
pPython = [−X, ℓh cos h − A sin h, A cos h + ℓh sin h]ᵀ
pC++ = [X, ℓh cos h + A sin h, A cos h − ℓh sin h]ᵀ

The comparison shows why the same raw angle tuple can give different results in the two models. It compares the algebra; motor directions and calibration require their own checks.

How the controller changed

  1. May–June 2026

    Geometric Python prototype

    The Python FK/IK and motor-interface files show the earlier geometric convention.

  2. July 30, 2026

    Compare IK increments with a Jacobian update

    I added a C++ tool to compare IK(pnext) − IK(pnow) with a damped-Jacobian position increment and save the results as CSV. Finite steps and damping mean the two calculations need not give identical increments.

  3. September 9, 2026

    Move toward matrix and vector state

    I refactored the controller to organize its state and commands as matrices and vectors.

  4. October 17–18, 2026

    Revisit the Jacobian and frame convention

    The commits record “New jacobian,” “frame convention improved,” and a return to the retained analytical FK/IK/Jacobian convention. I then checked that convention with an independent derivation.

What the comparison measures

The saved MATLAB comparison covers 6,000 poses and 3,200 ideal command intervals for a recorded October 18 model snapshot. The largest joint-increment difference between the retained and derived models is 8.89 × 10−16 rad. This measures agreement between the numerical models, not motor tracking.

Physical testing

Calibration and tracking still need physical tests.

The single-leg comparison is diagnostic: its foot position comes from applying FK to encoder readings, without an independent foot-position measurement. Some controller files differ from the saved verification snapshot. Gait robustness and hardware performance still need their own tests.
