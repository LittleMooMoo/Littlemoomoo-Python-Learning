Start with the geometry

I first reduced the leg to a hip offset and a two-link sagittal triangle. The early notes connect a coordinate sketch with trigonometry, then use the cosine rule to recover joint angles.

Geometric IK in the earlier Python convention
a = √(y² + z² − ℓh²)
r = √(x² + a²)
κ = acos[(ℓs² + ℓt² − r²) / (2ℓsℓt)]
β = acos[(ℓt² + r² − ℓs²) / (2ℓtr)]
h = π/2 − atan2(y,z) − atan2(a,ℓh)
t = β − atan2(x,a),   s = π − κ

This historical model uses millimetres: ℓh = 84.26 mm and ℓt = ℓs = 270 mm. Its implementation clamps square-root and acos arguments and rejects a degenerate zero-length triangle; it is not a complete unreachable-target filter.

Re-derive the leg through a transform chain

In the later derivation I expressed each joint rotation and link translation explicitly. The retained C++ leg convention is x forward, y right, z down, with h about −x, t about +y, and relative knee angle s about −y.

Retained C++ transform convention
T01 = Rx(−h) Ty(ℓh)
T12 = Ry(t) Tz(ℓt)
T23 = Ry(−s) Tz(ℓs)
T03 = T01T12T23

Rotations are proper rotations; translations and joint axes must use the stated frames. The first three components of T03[0,0,0,1]ᵀ give the foot position.

The current per-leg geometry uses ℓt = ℓs = 0.27 m and signed hip offsets ±0.07456 m. These parameters and angle conventions differ from the earlier Python model.

Every column corresponds to one stated joint coordinate. For example, ∂y/∂h = z and ∂z/∂h = −y expose the hip-rotation structure. Entries have units m/rad.

Return from foot position to joint angles

Current C++ IK branch
a = √(y² + z² − ℓh²)
c = (x² + a² − ℓt² − ℓs²) / (2ℓtℓs)
s = acos c,   B = ℓt + ℓs cos s,   D = ℓs sin s
h = atan2(ay − ℓhz, ℓhy + az)
t = atan2(Bx + Da, Ba − Dx)

The implementation checks finite inputs, hip-plane reach, the cosine-rule reach condition, and indeterminate cases before accepting this branch. The mathematical branch still needs a matching physical joint reference.
